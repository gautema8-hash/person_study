## 二、过程中发现并澄清的问题

1. **冷启动带 `%23` 编码深链白屏**：`am start -d ".../%23/..."`（%23 代替 #）在浏览器冷启动时渲染空白——属系统浏览器对编码 hash 的处理问题，非 App bug；App 内 hash 路由与热状态下深链均正常。**对打包 APK 无影响**（Capacitor 用真实 `#` 与自身 WebView）。
2. **继续/目录按钮对 `adb input tap` 不响应**：本地 Playwright 与桌面 E2E 点击均 PASS，判定为合成事件兼容性问题而非 App bug；留一条改进项——给 `.btn` 增加 `@touchend` 兜底可进一步增强（P2，未实施）。
3. 打开方式选择框（钉钉/浏览器）：系统行为，选「仅一次」即可，不影响 App。

# 增补：APK 真装测试报告（返回/退出逻辑专项）

**日期**：2026-10-30 ｜ **APK**：`app-debug.apk`（4.8MB，Capacitor 6 + Gradle 8.2.1 + AGP 8.2.1 + JDK 17）
**安装**：`adb install -r` 成功，`com.rszx.renshengzhexue/.MainActivity`

## 实现要点

- 硬件返回键由 `@capacitor/app` 的 `backButton` 事件接管（仅原生环境，Web 端不受影响）
- **层级返回**：按路由语义父级回退——条目→章节→目录/检索→首页（`parentOf()` 映射，不依赖 WebView 历史栈，深链冷启动也正确）
- **首页栈底双击退出**：两次返回键间隔 ≤2000ms → `App.exitApp()`；否则 Toast「再按一次退出人生哲学」（@capacitor/toast）
- **3 秒重置**：第一次按下后 3 秒内无第二次 → `lastBackAt=0` 取消确认，需重新双击

## 真机实测结果（小米 15，4/4 通过）

| # | 用例 | 操作序列 | 期望 | 结果 |
|---|---|---|---|---|
| A | 首页单次返回 | 首页按返回 ×1 | 弹 Toast、不退出、App 仍前台 | ✅ Toast「再按一次退出人生哲学」可见，topResumedActivity 仍为本 App |
| B | 双击退出 | 返回 ×2（间隔 0.5s） | App 退出前台 | ✅ MainActivity 结束，前台切回后台任务（pid 缓存属正常） |
| C | **层级返回** | CDP 导航至条目页 #/entry/5/1 → 返回键 ×3 | entry→chapter→toc→home 逐级 | ✅✅✅ `#/chapter/5` → `#/toc` → `#/` 三连 PASS |
| D | **3 秒重置** | 按1次 → 等 3.5s → 按1次 → 隔 1.2s → 按1次 | 重置生效则末两次间隔 1.2s<2s → 退出；若失效则按 5.2s>2s → 不退出 | ✅ App 退出 = 重置逻辑实证 |

> 测试 C 导航精度：debug 构建开启 WebView DevTools（`webview_devtools_remote_<pid>`），经 CDP `connect_over_cdp` 精确点击导航，硬件返回键用 `input keyevent 4` 注入，路由状态用 `location.hash` 实读断言。

## 结论

**返回/退出逻辑在真实 APK 环境全部验证通过**。已知说明：`exitApp()` 后 Android 会保留进程缓存（pid 不消失属系统行为，判断退出以 Activity 栈为准）；APK 退出后系统会将后台任务（此前测试用的浏览器 PWA 版）顶回前台，两者 localStorage 隔离（继续阅读进度不同可证）。
